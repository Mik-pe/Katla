Discovery clearly exposes three coverage controls through the material schema: `alpha_mode` enumerates `opaque`, `mask`, and `blend`; `alpha_cutoff` is nonnegative, defaults to 0.5, and is described as hiding the whole masked surface above 1; `double_sided` renders both faces with reversed back-face shading normals. Opaque ignores alpha, mask rejects sampled alpha below cutoff, and blend composites back-to-front without scene depth writes. Base-color RGB remains sRGB and alpha remains a linear 0..1 multiplier. The existing phrase `alpha does not switch render mode` is accurate: setting alpha and selecting the coverage mode are separate actions.

The presets receipt (#2) additionally exposes editable coverage flags and explicit blend policies: depth testing enabled, scene depth writes disabled, nonzero-alpha surfaces pickable with a separate picking depth buffer, and blended surfaces excluded from binary shadow-map shadows. Preset values show opaque mode, cutoff 0.5, and double-sided false. This was enough information to construct the requested experiment without shader knowledge. The normal-scale description also now states finite values, negative-axis inversion, and a typical 0..2 range, addressing a friction point from my preceding session.

For my workflow the coverage API is straightforward: precise factors, explicit mode selection, partial-patch preservation, before/after receipts, and inspectable coverage values let me reason about state without code access. Explicit picking policy is especially useful because seeing the sphere through the panel could otherwise suggest that the sphere should receive the pick. The native center pick behavior matched the discovered foreground nonzero-alpha policy. Arbitrary screen-coordinate pick sampling is not exposed; editor_view offers current center/pointer results, and the pointer was null throughout this task. I chose a controlled camera alignment to get a useful test pixel.

My preferred affordances, specific to this participant, are an editor_view pick action accepting normalized image coordinates, a compact material description that explicitly names coverage controls alongside PBR factors, an example combining `alpha_mode: blend` with linear alpha, and structured field-specific error data in addition to the already clear cutoff error text. Returning supported primitive shape names would remove the cube-name guess used here. Material inspection should eventually expose texture-slot presence and import provenance so a sampled-alpha threshold can be explained for textured assets. Linking material mutation receipts to the committed frame incorporating them would make native comparisons more direct. These are authoring preferences from one contextual session, not claims about what LLMs universally want.
