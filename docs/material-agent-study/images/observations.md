## Friction and requested improvements

- Direct reuse of an inspected `source` works. Separating round-trippable source from metadata is useful; the original image's `image_source` annotation now sits outside `source`. The distinction between retained original records, active flags and authored choices makes neutral versus inherit understandable.
- Neutral/inherit receipts differ in completeness: neutral includes null image and sampled space; inherit returns only source. An explicit effective/current image summary for inherit would reduce the follow-up inspect needed to confirm restoration. Document neutral values by role (for example albedo white, normal flat) so authors can predict the visual result from discovery.
- Resource input was canonicalized to absolute File output on assignment. Same-machine persistence succeeded. This episode does not establish portability after moving the project. Clarify whether saved references retain project-relative intent, or expose original requested and resolved asset references separately.
- Schema descriptions explain Asset variants, but `asset` itself is only typed as object. A discriminated schema for Resource/Scene/File, including absolute/relative requirements, would make discovery more precise.
- Missing-file errors do not name the requested path, role or affected IDs. Stable error code plus those fields would help recovery; image-index errors could also list the available indices. Nonmesh errors embed `Entity(28:0)` in prose rather than returning a decimal ID field.
- Imported metadata calls format `decoded_format: R8G8B8`, whereas authored image metadata calls it `format: R8G8B8A8Srgb`. These may describe different decoding/GPU representations; label them explicitly so a user does not mistake the format change for a color-space inconsistency. Source sRGB and sampled linear are otherwise clear.
- The fixture alpha experiment confirms image alpha alone and render mode are separate controls. A receipt warning/info field about ignored image alpha under opaque mode could help when users expect holes automatically, without changing mode implicitly.
- Original/current normal-UV provenance now separates `original_generation_uv` from `current_normal_uv`, addressing the ambiguity observed in the sampling study. I did not change normal UV transforms in this episode or validate tangent math.
- Inspection remains long and repeats all capabilities/roles. Optional compact/role inspection and source-image thumbnails would help iterative authoring. History still returns a viewport without an explicit affected-role/source receipt.

The native images prove the observed appearance changes in this one editor episode. Exact state/persistence conclusions rely on receipts and inspection comparisons. I did not test every image format, cross-role interpretation, moved-project path resolution, blended transparency or another backend.
